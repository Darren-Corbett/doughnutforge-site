**It can be, but only if two things are right: the encryption method and the password.** A ZIP file locked with modern AES encryption and a long, random password is hard for anyone else to open. A ZIP file locked with the older method, or with a short password, may keep out a curious colleague but not someone who is determined. How you send the password matters as much as the file.

## Two kinds of ZIP encryption

When you add a password to a ZIP file, the tool encrypts what is inside it. Not all ZIP encryption is the same. The ZIP tool WinZip describes two kinds: "strong AES encryption and weak Zip 2.0 (Legacy) encryption".

The older Zip 2.0 method gives some protection against a casual user, WinZip says, but it "cannot be expected to provide protection from individuals with access to specialized password recovery tools". Its advice is direct: "Do not rely on Zip 2.0 encryption to provide strong data security."

AES is the strong option. WinZip offers it as 128-bit or 256-bit, and 256-bit is the stronger of the two. The free tool 7-Zip also lists "Strong AES-256 encryption in 7z and ZIP formats" among its features.

## Why the weak method is still around

The older method has one advantage: almost everything can open it. WinZip says Zip 2.0 encryption is supported by "nearly all other Zip file utilities", while AES is supported by "some other Zip file utilities (but not all)".

That creates a trap. If the person you send a file to cannot open it, it is tempting to switch to the method that always works, which is the weak one. A better fix is for them to use a tool that can open AES files.

## The password matters as much as the method

Even the strongest method is only as good as the password. WinZip says the security of an encrypted ZIP file depends on "the strength of your password, including factors such as length and composition".

This matters more for a file than for an online account. A website can lock you out after a few wrong guesses. Someone who has a copy of your ZIP file can keep guessing for as long as they like, on their own computer.

The UK's National Cyber Security Centre (NCSC) warns that "weak passwords can be cracked in seconds". It suggests combining three random words to make a password that is "long enough and strong enough", or letting a password manager create one: "The NCSC encourages people to use password managers".

Use a new password for each file you send, and never one you already use for an account.

## Send the password a different way

If the password travels in the same email as the file, anyone who sees that email has both. The UK Information Commissioner's Office (ICO) is clear: "Do not include the password within the same email as the encrypted file attachment." It advises that you "communicate the key to the recipient over a separate communication channel", for example by phone once the file has arrived.

## A quick check before you send

1. **Choose AES.** If your tool offers a choice, pick AES, and 256-bit if it is offered. Avoid Zip 2.0 or "Legacy".
2. **Use a long password.** Three random words, or one made by a password manager.
3. **Use it once.** A new password for each file, never one from an account.
4. **Send the password separately.** A phone call or a message in a different app, never the same email.
5. **Check they can open it.** If their tool cannot open AES files, help them find one that can, rather than switching to the weak method.

## What a password-protected ZIP file does not do

- **It does not protect the files once they are opened.** After the other person types the password, the files are ordinary files on their device.
- **It opens for anyone with the password.** If the password is forwarded, written down or reused, so is access to the file.
- **It cannot be taken back.** Once the file is sent, you cannot change its password or withdraw it.

For what encryption can and cannot do more generally, see [Does encryption protect against hackers?](https://doughnut-forge.app/blog/does-encryption-protect-against-hackers/)

## Another way: no password to send

The weak point in all of this is the password. It has to be chosen, remembered and passed on, for every file. Public-key encryption takes it out of the journey. Each person has a private key that stays on their own device, and a public card they can share with anyone. A file locked with someone's public card opens only with their private key, so nothing secret travels with it. [How to share encrypted files with someone you trust](https://doughnut-forge.app/blog/share-encrypted-files/) explains how this works, step by step.

[Doughnut Forge](https://doughnut-forge.app/) works this way. It has no password-protected files, so there is no file password to choose or send: you encrypt a file for the people you choose, and they open it with their own identity. Both of you need the app, and you swap contact cards once before the first file. For a one-off file to someone who does not use it, a ZIP file with AES encryption and a strong password, sent separately, is the practical choice.

## The short answer

A password-protected ZIP file is secure when it uses AES encryption, a long password used only once, and a password sent a different way from the file. Without those, treat it as a lock that keeps out the curious, not the determined.
